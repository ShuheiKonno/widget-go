スキン案「紙テープ」PAPER TAPE

ui/index.html と ui/settings.html の実 DOM・クラス名・CSS 変数をそのまま使い、 スキン 1 案を実寸で組み直したモックです。数値・SSID・モデル名はすべてダミー。幅 230px（フル）と 130px（コンパクト）は実機と同じで、 スキンは data-skin と CSS 変数の差分だけで表現しています。アプリ本体のコードは変更していません。

コンセプト

紙テープPAPER TAPE

計測ログを印字した紙テープを、そのまま窓にしたスキン。等幅の数字、破線の罫線、朱と藍の2色印刷、角丸なし。装飾を足すのではなく、面・罫線・インクの3要素まで削ることで、常時表示していても視界の主役にならない静けさを狙います。

opencode の「ターミナルに常駐して、淡々とログを出す」性格を、UI の側から写した案です。

テーマ・透過との関係

併存（置き換えない）。スキンは「インク・罫線・書体・角」のレイヤーだけを担当し、ダーク / ライト / システムが紙の地色を選びます（ダーク＝夜の黒紙、ライト＝生成りの紙）。

透過モードはウィンドウ全体のアルファ（Go 側の SetLayeredWindowAttributes）なので、スキンとは独立して効きます。--container-bg のアルファ値はスキンでも変えません。

実装の形

body[data-skin="paper-tape"] で変数を上書きし、差分ルールは 8 個だけ（角丸・破線・目盛りバー・アイコン記号など）。data-skin なしは現行と同一。config.json には skin を 1 キー足す想定で、テーマ・透過の保存値には触れません。

下のツールバーで「既定（現行）」に切り替えると、レイアウトが動かないことを確認できます。

デザインノート（実装に渡すときのメモ）

1. なぜこの見た目か

  • 2色印刷に限定。朱（CPU・NPU・クロック・Claude）と藍（メモリ・GPU・Codex・受信・稼働中）の 2 色だけ。現行の紫→青→桃→橙という 4 系統のグラデーションを捨て、色数を減らすことで「今どこが動いているか」を色ではなく位置と数字で読ませます。使用率の警告（61%〜黄 / 81%〜赤）だけは意味を持つ色として例外にします。
  • 面を捨てて罫線に。区画の塗りと角丸を外し、上辺の破線 1 本で仕切ります。紙の罫線と同じで、区画が増えても画面が重くなりません。
  • 数字は等幅・桁揃え。値は font-variant-numeric: tabular-nums。更新で桁が跳ねないため、チラ見でも変化が読めます。
  • バーは目盛り。6px ごとに切れ目を入れた単色バー。グラデーションをやめ、印刷のゲージらしくしました（repeating-linear-gradient 1 行）。
  • アイコンは記号に。絵文字（💻🧠🎮🧩📶🤖）は紙面から浮くため、» ≡ △ ◇ ⇅ ✳ に差し替え。DOM は変えず、.section-icon の font-size:0 と ::before だけで実現します。

2. 実装方針（差分だけで足す）

1. 設定と保存

config.json に skin（既定 ""）を追加。設定画面の選択で /api/setoption?key=skin&value=paper-tape。テーマ・透過の値はそのまま。

2. DOM

変更なし。body に data-skin を立てるだけ（起動時と設定変更時）。クラス名・区画構造・JS の更新処理に手を入れません。

3. CSS 変数

[data-skin="paper-tape"] で約 40 個を上書き。既定値は現行のままなので、スキン未選択時の描画は 1px も変わりません。

4. 差分ルール（8 個）

角丸 0／区画の塗りを廃して上辺破線／目盛りバー／アイコン記号／電源スライダーの角形つまみ／上部ボタンの角形化／2色インク／設定カードの角形化。

5. グラフ色

受信・送信の色は現在 canvas 内にハードコードされているため、--net-rx / --net-tx に切り出す（このモックではインライン SVG で再現）。

6. 角丸の変数化

現在リテラルで書かれている 8px / 10px を --radius に置換（既定 8px、スキンで 0）。置換しない場合はスキン側で個別に上書き。

7. 絵文字の非表示

.section-icon は font-size:0 にし、区画ごとの ::before を 1 行ずつ。読み上げ用の aria-label は現状どおり親の見出しテキストが担う。

8. 設定画面

「表示」パネルにスキンカードを追加するだけ。カードのプレビューは静的な CSS 描画（画像ファイル不要）。

4. 未確定にしていること

  • 設定のラベル。「スキン」で通していますが、「デザイン」のほうが分かりやすいかもしれません。既存の「テーマ」との違いは、テーマ＝地色、スキン＝印刷の質感、という説明をヒントに置いています。
  • 既定の扱い。スキン未選択を「既定」として残す前提です。新規インストール時に紙テープを既定にするかは、別途判断が必要です。
  • 絵文字の差し替え。スキンでアイコンを記号に替えると、区画の意味が分かりにくくなる可能性があります。実際に使ってみて、» などが読みづらければアイコンだけ現行のまま残す選択肢もあります。
  • ライトの紙色。生成りの紙は暖色寄りなので、Windows のライトテーマ（寒色寄りの UI）と並べたときの差が大きめです。気になる場合は --container-bg を #f3f4f0 程度まで中立化できます。
  • ミシン目。左端の破線は装飾です。ウィンドウ幅を狭めたときに邪魔なら、.win::before を消すだけで外せます。
このモックで再現していないこと（実装時の確認事項）
  • 折りたたみ（シェブロン）の開閉アニメーションと、区画の並べ替え。DOM とクラスは現行のままなので、スキンは .collapsed の見た目にだけ影響します。
  • AI 使用量の「自動で反転 / クリックで反転」表示。コンパクトでは 2 行を並べる既定の見せ方だけを示しています。
  • 実際のトレイアイコン。スキンはウィジェットと設定ウィンドウが対象で、トレイの配色（tray.go）は別扱いとしています。
  • 数値のライブ更新。モックは静的ですが、桁揃え（tabular-nums）により更新時のガタつきは起きません。
  • 透過モードの正確な見え方。実機はデスクトップの上に窓全体のアルファが掛かるため、このページではチェッカー板と opacity で近似しています。
