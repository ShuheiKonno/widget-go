# 設定ウィンドウとスタートメニュー / スタートアップ登録

ウィジェットは狭く、設定を窓内のモーダルで出すと、設定が収まるまで窓の高さを広げる必要があった。
設定を別ウィンドウに移して広く表示し、あわせてスタートメニューとスタートアップへの登録を設定画面から行えるようにした。

## 設定ウィンドウ

- ⚙ ボタンは `/api/opensettings` を呼ぶ。Go 側（`settingswin.go`）が、メインと同じ UI スレッド・同じ Run ループの上に
  別の WebView2 ウィンドウを作り、`/settings`（`ui/settings.html`）を開く。
- 枠あり・リサイズ可・タスクバーに出る通常のウィンドウ。ウィジェットがあるモニタの作業領域の中央に、
  920×780（論理 px、DPI 倍率を掛ける）で出す。作業領域より大きくならないよう縮める。タイトルバーはテーマに合わせてダーク / ライト。
- 閉じると破棄する（メモリを解放。開くたびに作り直す）。開いている間に ⚙ を押されたら、前面に出すだけ。
  Esc でも閉じる（`/api/closesettings`）。
- **`WM_DESTROY` を握りつぶすサブクラス化が必須**。go-webview2 は `WM_DESTROY` で `PostQuitMessage` を呼び、アプリ全体が終了する。
  `aiusage/authview.go` の補助ウィンドウと同じ作り。`WM_NCDESTROY` で状態を片づける。
- ちらつき対策（`docs/startup-flicker.md`）と同じく、非表示で作り、位置を決めて完全な透明で表示状態にし、
  ページの準備完了（`/api/settingsready`）かタイマー（3 秒）で見せる。
- `/settings` は `/` と同じく、トークンなしで読める（CSP 付き。トークンは HTML に入る）。`/api/*` は従来どおりトークン必須。

## ウィンドウ間の同期

- 設定ページは既存の `/api/*` をそのまま使う（API の意味は変えていない）。
- 変更のたびに `/api/settingschanged` を呼ぶ。Go 側は、メインの WebView に `window.__settingsChanged()` を Eval で送り、
  設定ウィンドウのタイトルバーのテーマも合わせる。
- メイン側（`ui/index.html`）は、起動時の設定の適用を `applyServerSettings(s, initial)` に切り出し、通知を受けたら
  `/api/settings` を読み直して同じ関数で反映する。区画の表示/非表示・並び順が変わると、高さの測り直しと位置・サイズの保存も行う。
- 逆方向（ウィジェット側のピン留めなど）には、設定ページがフォーカスを得るたびに読み直して追従する。
- モーダルが無くなったので、`modalRestore` と、`adjustWindowHeight` の中のモーダル分の高さ計算は削除した。

## スタートメニュー / スタートアップ

設定画面の「起動とショートカット」で、チェックを入れるとショートカットを保存し、外すと削除する。

- ファイル名は `system-widget.lnk`（実行ファイル名に合わせた固定名）。同じ名前のファイルがあれば、作った経緯によらず利用者の登録とみなす
  （チェック済みで表示され、チェックを外すと削除される）。
- 保存先は、`%APPDATA%` から組み立てず、既知フォルダ（`FOLDERID_Programs` / `FOLDERID_Startup`）から取得する
  （フォルダのリダイレクトに対応）。
- チェックの状態は、ファイルの有無で決める（`config.json` には持たない）。外したときは `system-widget.lnk` だけを削除し、他のファイルには触れない。
- リンク先は、今動いている実行ファイル（`os.Executable()`）。設定画面に表示する。
  **リンク先が違うショートカットは、警告を出すだけで、自動では書き換えない**（検証用のビルドや `go run` の一時 exe を起動しただけで、
  利用者の登録が一時ファイルを指してしまうのを避ける）。「今のアプリに更新」ボタン、またはチェックを入れ直すと上書きされる。
- `.lnk` の作成は COM（`go-ole` の `WScript.Shell`）。WebView2 が UI スレッドで COM を STA として初期化済みなので、
  専用の goroutine で `LockOSThread` して `CoInitializeEx` する（`shortcut/shortcut.go`）。UI スレッドからは呼ばない。
- API: `GET /api/shortcuts`（状態）、`POST /api/shortcuts/set?kind=startmenu|startup&enable=true|false`。

## 確認方法

- 単体テスト: `go test ./shortcut/ .`（ショートカットは `t.TempDir()` に作る。保存先は差し替えられる）。
- 実機: ⚙ で開く／閉じる／開き直す（アプリが終了しないこと）、設定を変えてウィジェットに即座に反映されること、
  区画の非表示で高さが追従すること。ショートカットは、スタートアップ側でチェックして `.lnk` ができ、リンク先が今の exe であること、
  外して消えることを確認した（確認後は元の状態に戻す）。
- **ショートカットの実機確認は、Claude デスクトップ（MSIX 版）から起動したプロセスでは行わない**。このプロセスでは `AppData\Roaming` への書き込みが
  `%LOCALAPPDATA%\Packages\Claude_*\LocalCache\Roaming` に仮想化され、本物のスタートメニューに出ない（プロセス内からは「ある」ように見える）。
  exe は `C:\Users\shuhe\work` 配下などの仮想化されない場所へビルドし、エクスプローラーからダブルクリックで起動して確認する。
  （本物の `Programs` フォルダとスタートメニューの「S」の欄に出ること、外して消えることを、エクスプローラーで目視する。）
- **ブラウザで `/`（メインのページ）を開かないこと**。メインのページの起動処理が、実行中のウィジェットのウィンドウを
  リサイズ・位置保存してしまう。`/settings` を開くのは問題ない。
