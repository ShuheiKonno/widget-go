## 決定事項（2026-10-31、ユーザー確認済み）

- **AI 使用量とは独立した区画**（区画名 `work`、アイコン ⏱、見出し「勤務時間」）。並べ替え・表示/非表示・折りたたみは区画ごと。
  `config.json` の `hidden.work` / `collapsed.work` / `order` で扱う（AI のように別の ON/OFF 設定は流用しない）。
- **既定は非表示**（設定で ON にしたときだけ出す）。表示順の既定は末尾（AI の下）。
- 表示は `実勤務時間 (15分切り下げの時間)`。例 `7:52 (7:45)`。実勤務時間 = 現在 − 開始 − 昼休みとの重なり。
  - 設定で「15 分切り下げの時間も表示する」を OFF にすると、実勤務時間だけ（`7:52`）。既定は ON。
- **昼休みの間は計測を止める**。設定で変更でき、既定 12:00〜13:00。昼休み中は、数値・見出し・バーを**灰色**にする（黄/赤より優先）。
- **色**: 実勤務時間 ≥ 勤務時間（既定 7:45）で黄色。**勤務開始日の 22:00**（設定で変更可）以降は赤。赤が優先。判定は、15 分切り下げ表示の ON/OFF にかかわらず実勤務時間で行う。
- **開始**: 「勤務開始」ボタンで記録する。開始時刻は **押した時刻 − 補正**（設定「勤務開始の補正」、既定 3 分、0〜60）。
  会社のタイムカードを押してからアプリのボタンを押すまでの遅れを埋めるため。ボタンにも「3分前から」と出す。
  - 計測中は、開始時刻の横の − / + で 1 分ずつ微調整できる。開始時刻の手入力（`HH:MM`）もできる。手入力で開始したときは補正しない。
  - 補正した日は「押下 09:06 − 補正 3分」を開始の下に出す。
- **終了**: 「勤務終了」で表示を固定、「リセット」で未開始に戻す。
- **前日の持ち越し**: 手動で終了/リセットするまで継続する（深夜残業に対応）。開始から 24 時間を超えた計測と、前日に終了した計測は、未開始として扱う（読み取りでは config を書き換えない）。

## 設計

- 計算は Go の純関数 `workTimerSnapshot(cfg, now)`（`worktimer.go`）。`now` と `time.Location` は引数で受ける。
- 時刻は**分に切り捨てて**、RFC3339 の文字列で `config.json` の `workTimer` に保存する（`startedAt` / `pressedAt` / `endedAt`）。
  再起動しても継続する。壁時計なので、PC のスリープ中も進む（昼休みの外では加算される）。
- 昼休み・22:00 は `time.Date` で組み立て、開始日から現在の日まで日ごとに重なりを合計する（日付またぎ対応）。
- API: `POST /api/worktimer?action=start|stop|reset|setstart|nudge&value=`。応答は最新のスナップショット（フロントが即描画する）。
  状態の読み出し・検証・書き込みは `mutateConfig` のクロージャ内で行う。
  - `setstart` の `HH:MM`: 計測中は開始日に付け、未開始は今日に付ける。未来、または 24 時間より前は拒否。
  - `nudge`: `value=-1|1`。上限は現在時刻、下限は 24 時間前。
- 設定キー（`/api/setoption`）: `workTarget=HH:MM`、`workLunch=HH:MM-HH:MM`（始まりと終わりを 1 キーで送る。終わり > 始まり）、`workRed=HH:MM`、`workFloor=true|false`、`workLag=0..60`。
- `SystemData.WorkTimer`（非表示のときは null）。2 秒周期の `/api/system` で更新し、操作直後は POST の応答で即描画する。
- フロント: `ui/index.html` に区画を追加し、`hideableSections` / `collapsibleSections` に登録する。コンパクトは見出し 1 行（本文を隠す）。
  ボタン類は区画のドラッグ対象から外す。行数が変わる操作のあとは `adjustWindowHeight()` を呼ぶ。
- 設定ウィンドウ: 区画一覧に「勤務時間」を追加し（チェックは `hide.work`）、**AI 使用量と同じ独立した「勤務時間」タブ**に設定を置く（2026-10-31、ユーザーの要望。区画タブの中には置かない）。タブの先頭にも同じ `hide.work` のチェックを置く。
- **コンパクト表示からの入力（2026-10-31、ユーザーの要望）**: コンパクト（幅 130px）には入力欄を置けないので、区画のクリックで小さな別ウィンドウ（`/worktimer`、幅 340 論理 px、ウィジェットの左隣。左に入らなければ右。高さはページが内容を測って `/api/resizeworktimer` で合わせる。上限 350、下限 160。表示前に合わせるので、余白が残らない）を開く。作りは設定ウィンドウと同じ（`settingsWindow` を 2 つ目のインスタンスにし、タイトル・URL・位置の決め方だけを変える。サブクラス化プロシージャと `orig` はインスタンスごと）。タイトルは「勤務時間 - システムモニター」（多重起動の判定が `FindWindow` の完全一致のため、本体と同じにしない）。区画の CSS・マークアップ・JS は `ui/work/` の断片にして、本体と入力ウィンドウの両方に差し込む（時刻の確定まわりを 2 か所にコピーしない）。別のウィンドウでの操作は `window.__workChanged`（`/api/system` を読んで勤務時間の部分だけ描き直す。`updateData` は呼ばない）で反映する。
- テーマ: 入力ウィンドウを開いたまま設定でテーマを変えたときも、`/api/settingschanged` の通知（`notifyMainSettingsChanged`）が入力ウィンドウの `window.__settingsChanged` を呼び、テーマを取り直す（Codex レビューの指摘）。
- カーソル: クリックできるところ（`[data-wk]`、時刻ピッカーの時計アイコン）は pointer。本体の `#dragArea` は `cursor: grab` なので明示が要る。コンパクトの勤務時間の区画は、区画全体が pointer（ドラッグ中だけ grabbing）。
- 時刻の入力欄（`<input type="time">`）は、時の 1 桁を打っただけで `change` が発火するため、`change` では保存しない。確定は Enter とフォーカス離脱（昼休みは 2 つの欄の組から離れたとき）だけ。
