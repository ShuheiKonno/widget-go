# 開発の進め方（教訓）

作業の進め方と、実機確認の注意をまとめる。v2.4.0 の作業（起動時のちらつき対策、設定の別ウィンドウ化、スタートメニュー / スタートアップの登録）で、advisor（アドバイザー）への相談によって、防げた不具合・見つかった原因が多かったため、記録する。

## 実装前にアドバイザーに相談する

複数ステップの変更、構造に関わる変更、OS や外部の挙動に依存する変更では、**調査（コードを読む、現状を確かめる）が済んだ時点で、実装に入る前に advisor ツールへ相談する**。完了を報告する前にも、もう一度相談する。行き詰まったとき、方針を変えるときも相談する。

v2.4.0 の作業で、相談によって防げた・見つかったもの:

- **ブランチの切り方**: 未コミットのちらつき対策と同じファイル（`main.go` / `server.go` / `ui/index.html`）を触る設定画面の改修で、「先に対策をコミットして、その上に切り直す」と助言された。衝突と、同じちらつきの再発を避けられた
- **設定を別ウィンドウに移す設計**: go-webview2 は `WM_DESTROY` で `PostQuitMessage` を呼ぶので、サブクラス化で握りつぶさないと、閉じるだけでアプリごと終了する。ウィンドウ間の同期、消した JS を呼ぶ箇所の洗い出しなど、漏れやすい点を実装前に挙げられた
- **ショートカット**: 保存先は既知フォルダから取る、COM は UI スレッドで呼ばない、リンク先は自動で書き換えない、名前を決める前に既存のファイルを確認する
- **完了前の相談で、実際の不具合を 2 件見つけた**: フォーカス時の読み直しが、直後の変更を古い値で上書きする競合。閉じてすぐ開き直したとき、前のタイマーが読み込み前の新しいウィンドウを早く見せる問題
- **「登録されない」の原因の切り分け**: Claude デスクトップ（MSIX 版）から起動したプロセスでは `AppData` が仮想化される、という仮説を立てられた。コードを直す前に、環境を疑えた

### 進め方

1. まず読む・確かめる（コード、設定、既存のファイル、実機の状態）。
2. 方針が固まる前に advisor を呼ぶ。会話の全体が渡るので、調べた事実を先に集めておく。
3. 助言と、自分で取得した事実が食い違うときは、黙って従わず、食い違いを示してもう一度相談して決める。
4. 依存の差し替えや、既存の仕組みの置き換えのような大きな方針変更は、advisor の助言があっても、実装前にユーザーへ確認する。
5. 完了前は、成果物をコミットか保存して残してから、最後の相談をする。

## 実機確認の注意（相談で分かったこと）

- Claude デスクトップ（MSIX 版）から起動したプロセスでは、`AppData` への書き込みが `%LOCALAPPDATA%\Packages\Claude_*\LocalCache\...` に仮想化され、本物のスタートメニューに出ない。ショートカット（.lnk）の確認は、仮想化されない場所（`C:\Users\shuhe\work` 配下など）に exe をビルドし、エクスプローラーからダブルクリックで起動して行う。詳細は `docs/settings-window.md`
- ブラウザで `/`（メインのページ）を開かない。起動処理が、実行中のウィジェットのウィンドウをリサイズ・位置保存してしまう。`/settings` を開くのは問題ない
- `golangci-lint` は `~/go/bin/golangci-lint.exe`（PATH 外）にある。PR の前に `golangci-lint run ./...` を実行する（今回は、`go vet` が通っても staticcheck の SA4006 で CI が落ちた。エラーを握りつぶす実バグだった）
- 確認用にビルドした exe は、`.gitignore` の `/system-widget.exe`、または `.claude/`（git 管理外）の下に置く
